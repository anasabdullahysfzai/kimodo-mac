Install NVIDIA Kimodo on an Apple Silicon Mac

Kimodo is NVIDIA's text-to-motion model. Its official setup targets Linux with NVIDIA GPUs. These are the steps and fixes that got its interactive demo running on a Mac.

Follow https://github.com/anasabdullahysfzai/kimodo-mac to install Kimodo on this Mac. Run downloads and servers in a real terminal, not a sandboxed shell.
Install by hand

Install

Tested on an M5 Pro MacBook Pro with 48 GB of memory, macOS 26, Python 3.11 and torch 2.15.

  1. Check you have what it needs

    • An Apple Silicon Mac with 32 GB or more of memory. The text encoder alone is a 16 GB language model.
    • About 25 GB of free disk, plus uv and git (brew install uv).
    • Hugging Face access to Meta-Llama-3-8B-Instruct. Request it, wait for the approval email, then log in with a Read token.
    Log in, then confirm access. It should print 200. 
    hf auth login
curl -s -o /dev/null -w "%{http_code}\n" -I -H "Authorization: Bearer $(cat ~/.cache/huggingface/token)" https://huggingface.co/meta-llama/Meta-Llama-3-8B-Instruct/resolve/main/config.json

    OpenRouter or any chat API can't stand in for Llama here. Kimodo reads the model's internal hidden states, so the weights have to run on your Mac.

  2. Clone Kimodo and create the environment

    mkdir -p ~/kimodo-local && cd ~/kimodo-local
git clone https://github.com/nv-tlabs/kimodo.git && cd kimodo
uv venv --python 3.11 .venv && source .venv/bin/activate
uv pip install torch
python -c "import torch; print(torch.backends.mps.is_available())"

    The last line should print True.

  3. Install without the motion-correction add-on

    Kimodo bundles a C++ extension written with Intel-only SSE/AVX instructions, so it can't compile for Apple Silicon. It only powers the optional Post Processing step, so skip it.

    SKIP_MOTION_CORRECTION_IN_SETUP=1 uv pip install -e ".[all]"

  4. Turn Post Processing off by default

    The demo turns Post Processing on by default, and without the add-on every generation would fail. This switches the default off.

    sed -i '' 's/^INIT_POSTPROCESSING = True/INIT_POSTPROCESSING = False/' kimodo/demo/config.py

  5. Download the models

    About 16 GB for Llama and 1.1 GB for Kimodo. If it stops, run it again and it resumes.

    hf download meta-llama/Meta-Llama-3-8B-Instruct --exclude "original/*"
hf download nvidia/Kimodo-SOMA-RP-v1.2

    Agents: Claude Code's sandbox blocks Hugging Face's file servers. Downloads stall at exactly 1.0 GB or fail with "No route to host". Run this in a real terminal.

    Still waiting on Meta's approval?

    Use the identical NousResearch re-upload in the meantime. Meta's Llama 3 license still applies. Afterwards, add TEXT_ENCODERS_DIR="$HOME/kimodo-local/text_encoders" in front of both launch commands in the next step.

    cd ~/kimodo-local
for r in McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp-supervised; do hf download $r --local-dir text_encoders/$r; done
sed -i '' 's#"meta-llama/Meta-Llama-3-8B-Instruct"#"NousResearch/Meta-Llama-3-8B-Instruct"#' text_encoders/McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp/adapter_config.json
hf download NousResearch/Meta-Llama-3-8B-Instruct --exclude "original/*"

  6. Start the text encoder, then the demo

    Use two terminals. Start the encoder first and wait for Running on local URL: http://0.0.0.0:9550.

    Terminal 1: text encoder on the Mac GPU 
    cd ~/kimodo-local/kimodo && source .venv/bin/activate && PYTORCH_ENABLE_MPS_FALLBACK=1 TEXT_ENCODER_DEVICE=mps TEXT_ENCODER_TMP_FOLDER="$TMPDIR/text_encoder" kimodo_textencoder
    Terminal 2: demo at localhost:7860 
    cd ~/kimodo-local/kimodo && source .venv/bin/activate && PYTORCH_ENABLE_MPS_FALLBACK=1 kimodo_demo
    Why the temp folder setting?

    On macOS, /tmp resolves to /private/tmp, which Gradio refuses to serve files from. Without the setting, the demo reports "Text encoder service is unreachable" and loads a second 16 GB copy of Llama on the CPU.

  7. Generate your first motion

    Open localhost:7860, close the welcome dialog and click Generate. The default "A person walks forward." took about 62 seconds for 6 seconds of motion in our test, because the motion model runs on the CPU. Leave the Post Processing checkbox off.

Prompts we tried

Results from our own runs in the demo, plus example prompts that ship with the Kimodo repo.

One body only

"A person kicks to the head of the other person" did not produce a head kick. Describing the leg itself did.

Wording raised the kick

Adding "in a fighting stance", "extremely high" and "above their head" took the kick from chest height to head height.

Spinning kicks stayed low

A spinning head kick stayed around hip height with one prompt box, a shorter prompt, and separate spin and kick boxes.

Settings in the demo

Model Parameters has Seed, Denoising Steps (default 100), Text Weight and Constraint Weight (both default 2.0). Num Samples generates several takes at once.

Troubleshooting

Errors we hit during setup, and what fixed them.

403 … not in the authorized list

Your Llama access isn't approved yet, or no token is set. Check the approval email, run hf auth login, or use the NousResearch copy from step 5.

Download stuck at 1.0 GB, or "No route to host"

You're running inside a sandboxed agent shell. Run the download in a real terminal; rerunning resumes it.

unknown type name 'FORCE_INLINE' / unsupported option '-msse4.1'

You're building the motion-correction add-on. Install with SKIP_MOTION_CORRECTION_IN_SETUP=1 (step 3).

incompatible architecture (have 'x86_64', need 'arm64')

An Intel cmake (e.g. MacPorts under Rosetta) built the extension. Skip the extension as in step 3.

motion_correction package is not installed

The Post Processing checkbox is on. Turn it off, or apply step 4 so it starts off.

Text encoder service is unreachable, falling back…

The encoder isn't running, or it's hitting the /tmp path issue. Stop the demo, restart the encoder with TEXT_ENCODER_TMP_FOLDER set, then start the demo again.

Tables of lora_A / lora_B "MISSING" and "UNEXPECTED"

Harmless. The pinned library versions try to auto-load the adapter first, then Kimodo loads it correctly. Linux shows the same output.
